# Changelog

## 0.1.6 — unreleased

The round *specimen findings*: faults the `delibera` and `trattato` specimens surfaced.

- **A letter-spaced word that Blink hyphenates no longer refuses the print.** The trailing-spacing vote counted the hyphen as a letter-spaced glyph, but Blink adds no letter-spacing to the hyphen it draws, so the hyphenated segment voted `-1` against the unanimous `0` and `decideTrailing` threw "letter-spaced segments disagree on trailing spacing" (the trattato's small capitals under `lang="it"`). The sample's glyph count now leaves the hyphen out; the unanimity rule is unchanged. `test/hyphenationLetterSpacing.test.ts` is the red case (`tempera­` 8 glyphs, ratio 7.019).
- **Text in an element that hides its overflow is clipped to its padding box.** Boxes and vectors were (`ancestorClips`), text was not: the trattato's contents leader, a long run in an `overflow: hidden` flex item, ran to the page edge in print only. A segment now carries the clips of its own element and its ancestors, measured by `textClips` (`vectors/cssBoxes.ts`, the same function with the walk starting at the element that holds the text), a line splits where its clips change, and the text item's new `clips` wrap the text object in the same `q`/`Q` as its `cm` (`lineWrap`). `overflow` is no longer taken from a non-replaced inline box, to which it does not apply. Not clipped: a colour cluster (emoji) and SVG `<text>`, whose own vector clips apply. `test/clipText.test.ts` is the red case, pixels beyond the box rendered with mupdf.
- **A generated number hung by `float` or `position` keeps its place.** `prepare` replaces a painting `::before` with a real span and did not copy `float`, `position` or the offsets, so a clause number hung by `float: left` or `position: absolute` became a block of its own above the clause text, on screen and in print (the delibera's clauses; the cause is here and not in Cicero, whose page only showed the prepared document). `NOT_COPIED` now holds `content` and the counter operations. `test/reifyHanging.test.ts` is the red case: a paragraph was one line taller after `prepare`, for both forms.
- **`styledBorders` defaults to `true`** (Egildo's ruling, 2026-11-02). A dotted or dashed border prints as written, where the default painted every one solid; `caster.styledBorders=false` is the opt-out. The corpus holds no styled border, so every committed PDF and display list is byte for byte what it was; the eight report snapshots change in their `options.styledBorders` field only, and `corpus.json` in its recorded commit. `test/options.test.ts` takes the new default.
- **`pngDecoder: 'canvas'` refuses by name.** No canvas decoder is built; the registry only declined to load fast-png under it, so a PNG that needed decoding refused blaming the flag that had been set. It now refuses beside `shaper: 'fontkit'`, `subset: 'pdf-lib'` and `convertRgb`, which move with it from `print` into `refuseUnbuiltTiers` (`options.ts`), where `test/options.test.ts` covers all four. Found by printing every flag from the command line.

## 0.1.5 — unreleased (branch `round/close-the-list`)

The round *close the display list*: a writer given the list and nothing else prints the same bytes, in the page and in node (DESIGN.md S102, *the same list prints the same bytes*).

- **The display list is version 5, and it carries everything the writer was handed or asked.** **The widths**: each font instance's `widths`, HarfBuzz's advances asked by the builder, which the writer's `/W` is and any writer's embedded `hmtx` must equal (S99, amended). **The creation date**: `info.created`, from the new `PrintInput.created` or the wall clock, written at whole seconds; the writer reads no clock. **`writing`**: the font profile and the colour story with its two ICC profiles as blobs. **Link URIs**: resolved by the builder into `target.uri`, and percent-encoded once (a space in an `href` reached the file as `%2520`). **`resources.fonts`** is an array that carries each instance's `key`, its order the order of `F0`, `F1`, …. **The structure tree** is the builder's, resolved by `displayList/structure.ts` with the writer's own rules moved unchanged (the pruning, every `/K` in reading order, the `/OBJR` last, an internal destination resolved to the element with a page, the attribute objects written out); a content start, a link, a destination and a bookmark name their element by index, and `figureBoxes` and a content start's `mcid` and `seq` are gone. **Every image source is what the writer embeds**: `images/imagePass.ts` runs in `print()` before the builder, asks the browser for the pixels of a WebP, AVIF or GIF and runs the opaque-photo rule and its JPEG re-encode, once per `src`; a source is a file (`blob`, `mime`), pixels (`samples`, RGBA) or the rule's `jpeg`, with `photo`, `original` and an arithmetic JPEG's `refusal` for the report, and `writing.photoRule` is gone. The writer refuses a list of any other version.
- **`emitStructure(list)` takes the list and nothing else, and returns `{ bytes, records, pageStreams? }`.** Its `fontProfile`, `color`, `photoRule`, `baseUri`, `toUnicode` and `originOf` options are gone, with three it was never passed (`decoderComparison`, `conversion`, `emoji`). It builds ToUnicode from the list's clusters (a refusal names the list item, `CasterError.listItem`, which `print()` turns into the element), derives `/P`, `/Pg`, the ParentTree and the IDTree from the children, writes an attribute object's keys in the schema's order whatever order the list holds them in, and deflates the image streams with pdf-lib's pako instead of `CompressionStream`. The records (`WriterRecords`) are what it chose, keyed by page and item; `ImageUse` is plain data. `recordsOf(list, records)`, new in `displayList/records.ts`, makes everything the report derives from them, and `print()` joins the measurement by the item; `buildOutline` writes and `outlineItems` makes the report's items. `report.ms` gains `rasters` and `images`, split off `emit`.
- **`validateList(list)`**, new in `displayList/validate.ts`: the refusals of a list the writer could not write, each a sentence (the version, the blobs, the font instances and their widths, the image and raster keys, each page's marked content, the links' orders and targets, the tree, the attribute keys). The writer calls it first; the tree checks moved there from the writer.
- **The schema is one file and the records another.** `displayList.ts` defines every type the list is written in and imports nothing; `displayList/contract.ts` holds what a writer returns, `CidFontStats`, `ReportPaint` and the colour record's types among them, and `displayList.ts` re-exports it. The modules that computed those types re-export them under their old names.
- **A new face, `@beltype/caster/display-list`**: the list's types, `validateList` and `recordsOf`.
- **The writer's pure helpers have modules of their own**, moved unchanged: `coordinates/matrix.ts`, `fonts/clusters.ts`, `images/samples.ts`, and `colorantName` into `colour/colorResources.ts`. The dead `actualText` member leaves the walk's and the report's structure attributes.
- **The identity gate**, `scripts/identity.ts` with `record`, `check` and `replay`, prints eight documents through the CLI's door and masks no byte; replay validates each committed list and writes it in node with nothing beside it, byte-identical on all eight. The corpus is committed under `fixtures/lists/` (each file, its list, its report snapshot, and the blob pool by hash) with five small documents under `fixtures/roads/`; `@beltype/specimens` 0.1.0 is a devDependency for the paper.
- **Two files are re-recorded, each alone**: roads, for its one `/URI` string; roads and webp, for one image stream each and the offsets after it, at the move to pako (175 762 to 175 665 bytes, 15 794 to 15 750). Two report `xobjectHash` values change with the image pass, because the dedupe key is over what the writer embeds. Every other file and report snapshot is byte for byte what it was at 0.1.4.
- **Tests**: `test/displayList.test.ts` replays every committed list, holds `recordsOf` to the committed reports, the widths to HarfBuzz's in the page, the tree to the file mupdf reads, and `validateList` to nineteen refusals; `test/determinism.test.ts`, the same list written twice and with every order that is not data reversed, and the four orders that are data; `test/pure-writer.test.ts`, the import closure of the writer, `recordsOf` and `validateList` held to thirty modules by name with no DOM, clock, chance or environment but five excused timings. 234 tests, 234 pass.

## 0.1.4 — 2026-10-30

- **The flag table is declared in `@beltype/common`'s shape.** `options.ts` builds `casterFlags` with `defineFlags('caster', FLAGS)` and exports it from the package, so the command line can read the table. `FLAGS`, `DEFAULTS`, `resolveOptions`, `colourOn` and `CasterOptions` keep their names, rows, comments and messages; a bad option is still a `CasterError` carrying `flag` (`resolveOptions` catches the table's `FlagError` and rethrows it, the smaller diff than moving `CasterError` under `FlagError`). `title` and `lang` stay outside the table. No output moves. **A page that loads Caster 0.1.4 must map `@beltype/common/flags`** in its import map beside `errors`, `data-beltype` and `mime`: `options.ts` imports it, and a page whose map lacks it fails with `Failed to resolve module specifier`.
- **A variable face is pinned once, at `finish()`, over the glyphs it used.** `embedFace` no longer instances the whole face up front: layout takes its advances from fontkit's instance of the source, and one `hb_subset` call pins the axes and cuts the used glyphs together. The program's `hmtx` is read back for every used glyph, and an advance more than one font unit from the one layout used is refused, naming the face and the glyph. On the sample paper the emit stage falls from 250 ms to 117 ms. `glyf`, `loca`, `hmtx`, `/W` and the page streams are byte-identical to before; the embedded program's `head`, `hhea`, `maxp`, `OS/2` and sometimes `GPOS` differ, and `FontBBox` is the used glyphs' own. **Untested: a variable CFF2 face.** HarfBuzz 14.4.0 pins CFF2 without baking `HVAR` into `hmtx`, so the check is expected to refuse where earlier versions printed.
- **The widths are HarfBuzz's own.** `/W` takes the advance from the font the shaper already caches for the instance (`hbShaper.glyphAdvance`, passed to `embedFace` as `advanceOf`) instead of fontkit's, saving about 25 ms on the sample paper, and the check of the cut program's `hmtx` is exact. fontkit rounded six advances of the paper one unit differently from HarfBuzz; those `/W` entries and the `TJ` jumps beside them move by one unit. `embedCidFont` still uses fontkit's widths, with one unit allowed.
- **`font-kerning: none` and `text-rendering: optimizeSpeed` are read.** The first is `kern` off, the second turns the common ligatures and the contextual alternates off and keeps kerning, each unless the author asked for it back; both as Blink draws them, to within 2/64 px per cluster (DESIGN.md S100).
- **The shaper keeps HarfBuzz's fallback shaping.** `vendor/harfbuzz.wasm` and `vendor/harfbuzz.js` are harfbuzzjs 1.6.1 rebuilt with `#undef HB_NO_LEGACY` added to its config override (`scripts/rebuild-harfbuzz.js`; Emscripten 6.0.13 by digest, HarfBuzz 36cb489). A face that leaves its combining marks out of the GDEF classes, Arial Unicode's Hebrew points, no longer sets the next letter late by the mark's width: the file's letters were up to 21.6 px from Blink's boxes and are within 0.04 px. The wasm is 456589 bytes (was 426620), the glue 41194 (was 42823); the paper's file is unchanged apart from its dates. `test/unclassifiedMarks.test.ts`, red before (1600 against Blink's 1300), green after.

## 0.1.2 — 2026-10-30

- **A word Blink hyphenates is drawn as Blink lays it out.** With `hyphens: auto`, Blink draws a hyphen that is in no text node and reports its box inside the rects of the characters on both sides of the break. `splitByRect` took each character's first rect, so the first character after the break was filed on the line before it: "temp" / "erature", no hyphen, and the rest of the word set one character in. Each character is now placed by the rects that are its alone; the box the two share is the hyphen, which joins the piece before the break. That piece draws `hyphenate-character` (`auto` is U+2010, or U+002D where the face has no U+2010), and the text it stands for is a soft hyphen, so an extraction rejoins the word.
- **`test/hyphenation.test.ts`**, a host strip of one box read back with mupdf: red before ("Decomposition temperat", no hyphen), green after. 198 tests, 198 pass.

## 0.1.0 — 2026-10-29

- **Caster leaves the BelType monorepo.** `src/` moves from `packages/caster` of `github.com/egildo/beltype` (source: `main` at b46e5806, branch `round/the-caster-port`) into this repository, as TypeScript, by the org drill's codemod. The port is mechanical: each of the 74 emitted `.js` files reads the same as the `.js` it came from once both are minified with comments dropped. The code is unchanged.
- **Two codemod gaps closed on the way**: a cast whose closing parenthesis follows a line break (`as` may not follow one), and a stray `* ` before an `@property` tag.
- **`dist/` carries `vendor/` and `profiles/`**, because `capabilities` finds them relative to itself. `capabilities` is emitted by a second pass without `rewriteRelativeImportExtensions` (`tsconfig.capabilities.json` says why).
- **Faces**: `.` and the unstable `./internal/*`, which the editing tools use for the types of `options`, `report` and `adapters/strip`.
- **Tests**: 22 suites on `node:test` from `.ts`, 197 tests, the count they had in the monorepo. `vendor-bundles` serves the built `dist/` and launches Chromium through `test/launch.ts`, a copy of the monorepo's launcher. The other 23 stay in the monorepo with their helpers.
