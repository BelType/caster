## Unreleased

- **Text standing directly in `<body>` refuses the print, naming its words.** `<body>Hello there</body>` printed one empty page and a summary of 0 words, with no refusal. Cicero takes the body's element children into `<beltype-root>` and nothing else, so a bare text node is never cut or presented: it stays in the body, laid out above the pages, and the census of the conservation of words, which walks the root, never met it. `print()` now asks the strip's parent for text children the browser lays out and refuses naming the count and the words (*the conservation of words*, DESIGN.md S61, `assertNothingBeside` in `measure/conservation.ts`). The text is printed once Cicero presents it; until then the author wraps it in an element. `test/bareBodyText.test.ts` holds `fixtures/cast-bare-body-text/` and, as its control, the same words in a `<p>`; the corpus prints as it did.
- **The README describes this repository.** It said the package was private and unpublished, named the monorepo's `--printer` and Paged.js road as its doors, counted eight corpus documents where there are nineteen, and listed `npm run census`, `npm run profiles`, `jsconfig.json` and `.js` tests that are not here. The doors are now `beltype print` and a host's own strip, with the monorepo's copy named as its own; the commands are this repository's `pnpm` scripts.
- **Caster ships no CMYK profile, and the sRGB one is CC0.** `profiles/` held two Ghostscript profiles, from a ghostpdl directory the AGPL covers, in an MIT package. `srgb.icc` is now saucecontrol's `sRGB-v2-magic.icc` (736 bytes, CC0, licence quoted in `profiles/README.md`), and `default_cmyk.icc` left the package for `test/assets/`, where only the suite and the identity corpus read it. A new option, `profile` (the bytes of an ICC profile), is the output intent's destination for CMYK: without it the output intent carries the sRGB profile, and `convertImages: 'cmyk'` and `convertRgb: 'wasm'`, the two roads that convert to CMYK, refuse naming `profile`. `device-cmyk()` inks and `blackText: '100k'` write `DeviceCMYK` operands without a profile and are unchanged. Proved by `test/profile.test.ts`: the refusal, a print with no profile whose `/OutputIntents` holds the sRGB profile's bytes, and a print with a profile whose holds that profile's. The Rust writer reads the output intent's profile as CMYK only, so under `writer: 'forme'` a colour print with no `profile` refuses naming it (`test/profile.test.ts`) until forme accepts an RGB destination. The corpus is re-recorded (authorized for this branch): `roads`, `vector-roads`, `convert-text` and `convert-images` pass the Ghostscript fixture as `profile`, so the first two change only in the output intent's condition text and in the sRGB `/DefaultRGB` profile's hash, and the last two also in the source profile of the conversion (eight ink values move in the fourth decimal and four converted images' samples differ); every other document is byte-identical.
